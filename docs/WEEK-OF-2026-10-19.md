## Monday — the only live wrong-wage path

Everything here moves money to real people. Nothing else on the list does.

### 1. Cutover-aware per-day payroll · ₹14,850 live, ₹1,400 in the current week

`app/api/payroll-summary/route.ts:215-231`. Gross is
`picking_total + COALESCE(salary, muster_total, days_present × daily_rate)`, and the arm is chosen
**per worker-period**. One allocation anywhere in the window suppresses the day-rate arm for the
whole window, so a marked-but-unallocated day pays ₹0.

⚠ **NOT a blanket per-day fix.** `labor_transactions` paid the cutover windows — Medappa
2026-08-03→08-18, ₹2,53,450, stopping the day before the muster cutover, with the same clean
handover at every tenant. Paying those days per-day would be a **second** payment. Verified twice.

So the fix is per-day **after each tenant's last bulk entry only**:

| tenant | worker-days | ₹ | dates |
|---|---|---|---|
| Laxmi | 29 (14 workers) | 13,200 | 27–28 Aug, 7 Oct, **15 Oct** |
| Medappa Estates | 2 | 1,200 | 5 Sep, 14 Sep |
| Seshagiri | 1 | 450 | 28 Aug |

The correct rule already exists in the codebase twice: `app/api/reconciliation/route.ts:285-302`
chooses per day with `NOT EXISTS` on both assignments and picking, and payroll's own retention
basis at `:344-363` does the same. Gross is the only per-period figure in the file.

**Acceptance:** a weekly run and a monthly run containing it agree on every worker; a day already
costed by `labor_transactions` is never paid again. The harness is in
`scratchpad/payroll-audit-wip/` — 14 cases, all passing with 600 s timeouts (vitest's 5 s default
is what made them look like failures). **Extend it rather than writing a new one.**

## Friday — guards, then the product win

### 12. `activity_code` FK — free, do it

0 orphans on prod or dev. `account_activities` has the composite key in duplicate, so
`FOREIGN KEY (activity_code, tenant_id) REFERENCES account_activities (code, tenant_id)` validates
immediately, matching what `labor_transactions` and `expense_transactions` already have. Three app
paths guard it; the DB accepts anything. Tamper-proven.

### 13. The two-way-door guard — and build it on UI reachability, not HTTP verbs

Every tenant record a writer can enter should be viewable and correctable.

⚠ **My first attempt at this scan was wrong and nearly cost a wasted route.** Verb presence is a
bad proxy:

- **No PUT, fully editable** — `processing-records` and `pepper-records` upsert via
  `ON CONFLICT … DO UPDATE` and their tabs load the existing row by date. Correct by design.
- **Has a PUT, not editable** — picking's ripe/green, which accepted the fields while the UI
  rendered no inputs (fixed in #98).

So the guard must assert a **rendered input bound to each field the payload sends**, which is what
`tests/picking-entries-are-a-two-way-door.test.ts` now does. Genuine remaining gaps: `soil_tests`
(no form, no route, no reader), `pf_percent`, `allocatedCost`, `heldAfter`.

### 14. Per-block benchmarking — the highest-value product change available

Not prediction. **Prediction is blocked on data, not software:** nobody has 3+ seasons (HoneyFarm
has one harvest), and per block the varietal, plant count, planted year and irrigation flag are all
missing while rainfall is recorded per *estate*. Anything shipped before ~2028 is a guess with a
useless confidence interval.

Benchmarking needs none of that and works today — cost/block, cost/acre and kg parchment/acre all
compute, proven over a simulated crop year:

```
Kaveri A      28.50 ac   ₹24,040/ac   44.4 kg/ac
Kaveri Hill   12.75 ac   ₹54,638/ac   86.1 kg/ac
Slope North   41.00 ac   ₹19,069/ac   23.4 kg/ac
```

**But it runs empty on real tenants:** 75–100% of labour rows are unattributed for three of five,
and four of six have no block acreage. So pair it with making attribution unavoidable — default the
labour form's block to yesterday's, require acreage during onboarding. That is the moat, built and
starved of input.

## Five things this week taught, worth not relearning

1. **A mechanical signal is not behaviour.** Four self-corrections in two days — the ₹1.87 lakh
   that was already paid, a deliberately viewer-local clock, processing's upsert, and `lump_sum`'s
   deliberate clear-on-absent. Each time the shape looked conclusive and the behaviour differed.
2. **Fix the class, not the instance.** #85 gave picking an edit route; #93 then found two more
   routes with no day-cap mapping; #98 found the fields the edit route accepted but never rendered.
   Same bug, three passes, because the first sweep was never done.
3. **A guard must not trip on its own documentation.** Comment-stripping, learned on 14 Oct and not
   carried across until a guard refused correct code on the 16th.
4. **A guard must assert the property, not the implementation.** One pinned
   `numericInputValue(...)` and broke when the code *improved*.
5. **A deny-list protecting a destructive path fails open for everything new.** Seeding was guarded
   by one tenant name; three real estates passed it.
